# 一镜到底动画（书架封面 → 阅读器）

> 本文档记录 Inkvol 漫画/小说阅读器「打开 / 返回」动画的完整实现、调用方式与踩坑记录。
> 版本：M3.6（2026-11-16）。

---

## 1. 目标

从书架点书到阅读器、再从阅读器返回书架，视觉上是一段连续动画：

```text
书架真实 UI
→ 点击瞬间：黑色「迷你阅读器」容器（含黑边）从封面卡位置起飞
→ 背景全程保持真实书架 UI，不做任何渐黑
→ 黑色容器放大至全屏，首页就绪后在容器内淡入
→ 容器铺满全屏时切换到 Reader 路由
→ Reader 接管
```

返回则是反向：

```text
Reader
→ 全屏黑色容器（首页含黑边）从 Reader 位置缩回书架卡
→ 途中首页交叉回封面（保留原交叉语义）
→ 背景全程是真实书架 UI（返回瞬间即露出，无渐黑过渡）
→ 封面落回卡片
```

小说阅读器接入同一套状态机与 overlay，差异见 §12。

核心要求：

- 全程可打断；
- 中间不能有“抽一帧 / 硬切”；
- 背景全程保持原 UI，不做整屏渐黑；黑色只属于飞行容器自身的阅读器黑底；
- 打开结束后才真正切 Reader 路由，且 overlay 终帧与 Reader 首帧逐像素同构。

## 2. 状态机

`ReaderOpenController`（`app/src/main/java/com/inkvol/app/ui/components/ReaderOpenController.kt`）是唯一真源。

```text
Idle
  │  beginOpen()
  ▼
Preparing            ← 预打开书源 + 解码首页，封面停在书架卡
  │  beginOpening()  ← 首页 bitmap ready 或 160ms 超时
  ▼
Opening              ← 迷你阅读器容器飞行 + 首页容器内淡入
  │  markVisible()
  ▼
Visible              ← overlay 已移除，Reader 完全接管
  │  beginClose()
  ▼
Closing              ← 反向动画
  │  markIdle()
  ▼
Idle
```

关键状态：

| 字段 | 含义 |
|---|---|
| `phase` | 当前阶段 |
| `bookId` / `coverPath` | 打开的书 |
| `sourceRect` | 书架封面卡根坐标矩形 |
| `targetRect` | Reader 目标矩形（预测或实际） |
| `targetFromReader` | 是否已从 Reader 拿到实际矩形 |
| `contentAspect` | 第一页宽高比 |
| `contentBitmap` | 预解码的第一页 |
| `coverBitmap` | 预解码的封面 |
| `readerReady` | 第一页是否可交接 |
| `readerVertical` | 是否纵向滚动模式 |
| `sourceRectStale` | 阅读期间旋转/窗口变尺寸过，sourceRect 在当前布局下不可信 |
| `closingHold` | stale 的 Closing 起飞闸：容器保持全屏等书架回报稳定坐标，超时兜底放行 |

## 3. 会话复用

`ReaderOpenSession`（同文件）持有：

```text
book
source
loader(PageLoader)
startPage
firstPage(ImageBitmap)
coverBitmap(ImageBitmap)
```

`ReaderOpenViewModel`（`ui/components/ReaderOpenViewModel.kt`）负责：

- `startOpen(...)`：启动预加载；
- `cancelPreparing()`：Preparing 阶段取消；
- `preload(...)`：打开书源、创建 PageLoader、解码当前页和封面；
- `anchorPage(...)`：双页模式下选对目标半屏那一页。

Reader 直接复用这个 session，**不再自己 openSource**，避免重复解压/解码。  
小说阅读器复用同一机制，对应会话是 `NovelOpenSession`（见 §12）。

## 4. 时间轴

`InkvolApp` 里通过 `rememberReaderOpenTimeline(controller, durationMs)` 创建。

只保留 **一个 `Animatable progress`**，`handoff` 是 draw 阶段的纯函数，不是第二个 Animatable。

```text
progress：唯一主时间轴
durationMs：设置页可调（快 260 / 默认 280 / 慢 320 / 更慢 360）

背景渐黑          = 已移除（背景全程真实 UI）
容器圆角          = 等比放大（保持封面卡圆角比例，上限 28dp）；打开方向全程圆角（Reader 黑底垫底，黑圆角不可见，交接无缝）；返回方向仅首帧 5% 行程直角对齐 Reader 末帧，随后圆角长回
handoff(首页/封面) = 仅返回交叉：smoothstep(progress, 0.54, 0.90)
路由切换          = progress >= 0.98（容器黑底此时已近乎铺满全屏）
markVisible       = progress >= 0.995 且 Reader 已上报实际矩形（targetFromReader，200ms 超时兜底）
```

首页淡入：起飞时首页已就绪（常态）则点击瞬间直接显示；中途才就绪则从就绪时刻起 120ms 容器内淡入。

## 5. overlay 绘制

`ReaderOpenOverlay`（`InkvolApp.kt`）只在 `Opening / Closing` 渲染。

```text
Canvas(fillMaxSize + pointerInput 消费输入)
  └─（小说返回且路由未退栈：先画满屏正文底色，遮住尚未卸载的阅读器）
  └─ clipPath(容器圆角矩形)
       ├─ drawRect(容器色)        漫画=黑底；小说=正文背景色
       ├─ drawImage(pageBitmap)   首页/正文页，alpha：打开=fadeGate，返回=handoff
       └─ drawImage(coverBitmap)  封面（仅返回），alpha = 1 - handoff
```

两层矩形插值（同起点、终点不同）：

```text
容器矩形 C(p) = lerp(封面卡矩形 → 全屏根矩形, p)
首页矩形 P(p) = lerp(封面卡矩形 → Reader 实际可视矩形, p)
```

p=0 时容器与首页同形（封面卡形态，无黑边）；p=1 时容器=全屏黑底、首页=实际可视矩形，与 Reader 首帧逐像素同构。首页位图在容器内，corner 由容器 clip 统一裁出。

容器圆角（B 档等比放大）：

```text
半径 = min(14dp × (容器宽 / 封面卡宽), 28dp) × 圆角闸
圆角闸 = 打开恒 1；返回 = 1 - smoothstep(progress, 0.95, 1.0)
```

等比放大保持封面卡的圆角比例，观感全程是圆的；上限 28dp 压住末段收角幅度。打开方向全程圆角——切路由后 Reader 黑底垫在 overlay 下方，黑底上的黑圆角不可见，撤除瞬间与 Reader 直角首帧无缝；返回首帧没有黑色兜底（底下已是书架 UI），所以只在 p=1 处直角对齐 Reader 末帧，14ms 内圆角长回。

绘制要点：

- progress/handoff 全部在 `DrawScope` 内读取，每帧只 redraw，不 measure/layout/composition；
- 首页目标矩形直读 `controller.targetRect`（Reader 上报实际值后立即生效，保证交接帧零偏差）；
- 采样质量用 `FilterQuality.Medium`；
- `alpha <= 0.001` 不画；
- 打开阶段不画封面（无封面的书也能播打开动画）；返回阶段封面缺失时走 `AsyncImage` 兜底；
- 横向模式内容用 Crop 源裁剪，纵向用 `FillWidth + TopCenter` 源裁剪。

## 6. 路由切换时序

这是最关键的拆坑点。

```text
Opening 期间：currentRoute == Library，不导航
progress >= 0.98 且内容可用：navigate("reader/{bookId}")
currentRoute == reader 且 progress >= 0.995：
    等待 targetFromReader（Reader 上报实际矩形，200ms 超时兜底）
    withFrameNanos { }   // 等 Reader 先组合一帧
    markVisible()
```

Reader 路由的 enter/exit/pop 转场都是 `None`，视觉完全由 overlay 状态机接管。  
小说 `novel-reader/` 路由同样禁用转场，并使用同一套 0.98 / 0.995 阈值。

## 7. 返回逻辑

`closeReaderOpen(reason)`：

```text
Preparing → cancelPreparing()
否则：
  show(systemBars)         先恢复状态栏 inset
  beginClose(reason)
  if currentRoute == reader → popBackStack()
```

`Closing` 期间 Library 重新组合时，书架卡通过 `updateSourceRect()` 回报当前位置，保证封面飞回最新卡片位置。

小说返回的额外护栏：`ReaderOpenOverlay` 传入 `novelReaderMounted`，当 `novel-reader/` 路由尚未真正退栈时，先铺一层不透明正文底色，避免收缩容器外透出仍在挂载的阅读器正文。

**书架网格滚动位置恢复**（与一镜到底配套，`LibraryScreen.kt`，终版见 §9.14）：

```text
离开书架（进阅读器）：DisposableEffect.onDispose 把 gridState 的
    firstVisibleItemIndex/offset 存入进程级 LibraryGridScroll（ScrollToTop.kt）
返回进入书架：
    网格状态 = remember { LazyGridState(LibraryGridScroll...) }  非 saveable，
        首帧状态即保存位置（不走 NavHost saveable，其快照不可靠）
    立即派发 scrollToItem + 逐帧重申（≤40 帧，防新网格前几帧重置锚点）
    数据稳定（totalItemsCount 连续两帧不变）后再重申一次
Closing 期间（closingHold）：挂起状态栏控制、头部折叠的手势消费、reset 效果三处，
    防恢复前旧位置 (0,0) 与 prefs null→加载 的 viewMode 变化翻乱折叠态
```

折叠态初值同样读 `LibraryGridScroll`，保证返回首帧视口与保存时一致。
（2026-11-15 起折叠量由滚动消费实现、列表 offset 可能仍是 0，另加
`LibraryGridScroll.collapsed` 一位记录离开时的折叠态。）

## 9. 踩坑记录（重点）

### 9.1 `markVisible` 漏加 `currentRoute` key

**现象**：打开后点击无响应，日志只有 `Opening → Closing`，永远没有 `visible`。

**原因**：

```kotlin
LaunchedEffect(phase, readerReady, contentBitmap) {
    if (currentRoute == "reader") { ... }  // 启动时还是 Library，false，之后不重启
}
```

`currentRoute` 从 Library 变 Reader 后 effect 不会重启，`markVisible()` 永远不执行，overlay 一直挡住点击。

**修复**：把 `currentRoute` 加进 effect key。

### 9.2 `handoff` 做成第二个 Animatable

**现象**：动画中段抽帧。

**原因**：progress 和 handoff 两个 Animatable 每帧各写一次状态，overlay 依赖两者，导致多次 snapshot apply。

**修复**：只保留 `progress`，`handoff` 改成 draw 阶段纯函数。

### 9.3 路由切换和内容交叉叠在同帧

**现象**：封面切内容时抽一帧 / 硬切。

**原因**：Reader 路由挂载 + ReaderContent 初始化 + 系统栏隐藏都发生在交叉中间。

**修复**：动画完整在 Library 上播完，`progress >= 0.94` 才切 Reader；交叉提前到 `0.54 → 0.90`。

### 9.4 overlay 用 AsyncImage + 动画 size

**现象**：动画中段偶发卡顿。

**原因**：size 每帧变化，Coil 可能按新 target 重新请求/解码。

**修复**：Preparing 阶段预解码封面成 `ImageBitmap`，overlay 用 `Image/drawImage`。

### 9.5 宿主每帧全量重组

**现象**：动画整体卡。

**原因**：在 `InkvolApp` 顶层读 progress/handoff，每帧重组 Scaffold + NavHost + chrome。

**修复**：progress 隔离到 timeline，宿主只传 `State` 给 overlay/effects，composition 不读 `.value`。

### 9.6 重复 hide systemBars

**现象**：打开动画中途 relayout。

**原因**：`postDelayed(hideBars, 240/800)` 在动画期间再次触发 insets 变化。

**修复**：只在路由挂载时 `hide` 一次。

### 9.7 覆盖 Compose 根视图 insets 监听

**现象**：退出阅读器后书架标题压状态栏，重启才恢复。

**原因**：曾在 `View` 上挂 `OnApplyWindowInsetsListener`，dispose 置 null 把 Compose 自己的分发也清了。

**修复**：不要覆盖根视图监听；退出时下一帧 `show(systemBars)`。

### 9.8 返回终点矩形过期

**现象**：旋转/滚动后返回，封面飞回旧位置。

**原因**：`sourceRect` 只在点击时记录。

**修复**：Closing 期间书架卡 `onGloballyPositioned` 继续 `updateSourceRect()`。

### 9.9 预测矩形用错比例

**现象**：封面目标矩形与 Reader 实际布局有偏差。

**原因**：预测用卡片矩形比例，而不是第一页真实比例。

**修复**：优先用 `contentAspect`（第一页比例）重算 targetRect；Reader 上报实际矩形后以实际为准。

### 9.10 双页 anchor page 选错

**现象**：双页模式下封面渐变到错误的半屏页。

**原因**：只预解码 startPage，没按 spread/RTL 选目标半屏那页。

**修复**：`anchorPage()` 按 spread 规则选择目标页。

### 9.11 圆角在末段收直角被肉眼看到

**现象**：v2 初版圆角闸 `1 - smoothstep(progress, 0.80, 0.98)` 让容器在最后 18% 行程收直角，用户要求「临切换也要圆角」。

**原因**：误以为终帧必须直角才能与 Reader 同构。实际上 navigate（p≥0.98）之后 Reader 的全屏黑底已经垫在 overlay 下方——**黑底上的黑圆角根本不可见**，markVisible 撤除瞬间圆角保持多少都无缝。

**修复**：打开方向删除收角闸，圆角全程保持；返回首帧没有黑色兜底（底下已是书架 UI），保留 `1 - smoothstep(p, 0.95, 1.0)` 仅在首帧 5% 行程直角对齐 Reader 末帧。

### 9.12 返回末段「内容叠标题」：两轮错误归因的教训

**现象**：返回动画最后瞬间，标题下面的内容叠到标题上一下再回落。

**走弯路**：两轮都归因到顶栏折叠状态机（`collapsed` 初值同步恢复滚动位置、`resetArmed` 跳过首组合强制重置），真机验证均未命中——用户场景里标题始终展开，折叠路径根本没参与。

**修复（真根因）**：Reader 隐藏系统栏，返回时 `closeReaderOpen` 先 `show(systemBars)` 再 pop，statusBars inset 有 ~250ms 回归动画，与返回动画时长几乎重合——实时 inset 让标题/chips/内容整体先高（inset≈0）后落（inset 回满），落在动画末尾被感知为「跳动」。

**落地方案**：书架页在 `Closing` 期间用冻结值替换实时 statusBarTop：

- `rememberSaveable` 保存进阅读器前（系统栏显示时）的 statusBarTop——恰好等于 inset 回归完成后的终值，跨路由保存/恢复；
- `rememberGlassHeaderState` 新增 `frozenStatusBarTop` 参数，`Closing` 时标题块/chips 行/网格让位三者同源消费，返回全程零位移；非 Closing 一律实时值，滚动自动隐藏状态栏等既有行为零变化；
- 两处试验性折叠改动按用户要求回退。

**教训**：①头部几何的 inset 来源必须同源——标题块原用 `safeDrawing`、chips 用 `statusBarsPadding()`、网格让位用 `statusBars`，三处各读各的，任何冻结/对齐方案都必须先把它们收拢到单一来源；②连续两轮理论修复未命中后，应转逐帧取证（模拟器复现 + 截图），不要再做第三轮猜测；③「整页一起动」和「内容相对标题动」是两种不同位移，用户描述里的相对关系是排查的关键线索。

### 9.13 返回后书架滚动位置「强行回顶」：三版方案迭代 + 日志取证定案

**现象**：书架滑到中间（非零 offset）打开书再返回，内容强行回顶；滑到最底打开再返回，不回顶。历史页（无显式 state、无回顶总线、无折叠头）从不回顶。

**三版方案与三轮弯路**：

1. **异步补滚**（`LaunchedEffect { 等 itemCount > index; scrollToItem(index, offset) }`）：判据 `count > index` 在数据只长到一半（count=5）时就满足，落位后随即被数据重构顶回 index 0；
2. **同步初始位置**（`rememberLazyGridState(initialFirstVisibleItemIndex = holder.index, ...)`）：被 NavHost 的 `rememberSaveable` 用旧快照 (0,0) 覆盖——saver 恢复优先于 init 初始值，首帧仍落 0；
3. 判据只查 `index > 0` 还漏掉了「item 0（viewHeader）内轻滚、index=0 但 offset>0」的场景（书架 viewHeader 是 item 0 且很高），恢复被静默跳过、一行日志都不出。

**取证方法（定案关键）**：加三路 `InkvolOpen` 诊断日志后让用户真机复现一次——①`diag grid pos` 在 t=0/120/400/1200ms 采样 `firstVisibleItemIndex/offset/totalItemsCount`；②回顶总线触发点；③`onDispose` 保存值。一次复现拿到三个决定性事实：

```text
saved   index=1 offset=569            ← 离开书架时位置正确
t=0ms   index=0 offset=0 count=5      ← 返回首帧：网格在顶部，只有 5 个 item
t=120ms index=0 offset=0 count=16     ← 数据在 ~120ms 内从 5 长到 16
（全程无 scrollToTop bus fired）      ← 排除回顶总线
```

**真根因**：返回书架后网格 item 数会**二次生长**（5→16，数据/结构非首帧就绪）。任何「首帧落位」或「早于数据稳定」的恢复都会被这次重构顶掉；NavHost saveable 恢复的还是旧快照 (0,0)。最底不回顶只是表象——offset≈0、夹在末位，重构后视觉无差。

**终版修复（两处）**：

- 恢复改「等 `totalItemsCount` 连续两帧稳定、且 > 目标 index 后再 `scrollToItem(index, offset)`」，落在数据生长结束后，重构不再能顶掉；判据放宽为 `index > 0 || offset > 0`；
- 折叠态初值 `collapsed` 改读进程级 `LibraryGridScroll`（gridState 首帧读数失真，读不到恢复前位置），返回首帧折叠态就位、`shelfGridTop=0` 与保存时一致，offset 不错位；
- 保存仍用 `DisposableEffect.onDispose`；冷启动 holder 为 (0,0) 自然回顶；进程被杀不持久化。

**教训**：①「A 场景跳、B 场景不跳」的不对称线索要优先吃透——本例「最底不回顶」直接证明不是"滚到 0"而是"夹紧落位差"，三层错误假设本可提前排除；②竞态/时序类问题不要连做三版理论修复，第二轮未命中就该上采样日志，一次复现胜过十次推演；③`rememberLazyGridState(initial...)` 的初始值会被 NavHost saveable 旧快照覆盖，凡依赖"初始位置"的恢复都不可靠；④`repeat { }` 是内联 lambda，不能 `break`，等帧循环用 `while`；⑤回顶总线（`MutableSharedFlow(replay=0)`）陈旧事件不会投递给新订阅者，但结论要用日志实证而不是背文档。

### 9.14 返回落地瞬间跳动：折叠状态机的三个隐藏写入者 + LazyGrid 首测量锚点重置

（9.13 的后续。现象演进三轮：整页下跳+顶部白条 → 标题展开又折叠 → 内容顶部↔原位跳动。）

**第一层：snapshotFlow 用恢复前旧位置翻折叠态。** `collapsed` 初值改读 `LibraryGridScroll`（正确=true）后，snapshotFlow 仍立刻采样到恢复前的网格旧位置 (0,0)，`scrollY=0 < 20` 把折叠态翻成展开 → `shelfGridTop` 0→148dp → 整页下跳、顶部露出标题展开区+背景白条；恢复落位后又翻回折叠。修复 = `closingHold`：Closing 期间挂起状态栏控制与折叠状态机（snapshotFlow collect 忽略位置更新，Idle 后效果重跑按恢复后位置确认）。

**第二层：无日志写入点——reset 效果。** 状态机稳了但「展开又折叠」残留，且采样日志里 `false -> true` 之前没有任何写 false 的记录 → 存在未埋点的写入者。全文件枚举三处写入：init（已埋点）、snapshotFlow（已埋点）、**`LaunchedEffect(resetKey) { if (resetArmed) collapsed = false }`（无日志）**。触发链：返回组合时 `resetArmed=false` 首跑跳过并置 armed=true → prefs 从 `null` 加载，`viewMode` 默认值→实际值 → `resetKey` 变化 → 效果重启 → armed 已 true → `collapsed=false`。修复 = reset 效果加 `closingHoldState`（`rememberUpdatedState`）守卫，Closing 期间不重置；真视图切换（Idle 时）照常生效。

**第三层：LazyGrid 新组装最初几个测量帧重置任何锚点。** 网格状态彻底脱离 saveable（`remember { LazyGridState(firstVisibleItemIndex, firstVisibleItemScrollOffset) }`，注意本版本构造参数**无 `initial` 前缀**）后，折叠状态机首采样即正确，但恢复日志显示构造即 (1,420)、首个测量帧后读数变 (0,0)，**立即派发的 `scrollToItem` 也被下一次测量冲掉**——新组装的 LazyGrid 在视口/数据/条目高度未就绪的前几帧会把任何锚点重置回 (0,0)，内容先画在列表顶部 ~120ms 后才拉回。修复 = **逐帧重申**：立即派发一次后每帧检查位置是否等于目标、不等就再派发（≤40 帧），布局一旦可绘制就落在保存位置；稳定后再重申一次防数据变化顶掉。

**终版恢复设计（`LibraryScreen.kt`）**：网格状态非 saveable、进程级 `LibraryGridScroll` 直接构造；恢复 = 立即派发 + 逐帧重申 + 数据稳定后重申；折叠态初值读 `LibraryGridScroll`（含 `collapsed` 位）；`closingHold` 挂起状态栏控制 + 折叠手势消费 + reset 效果三处。

**教训**：①状态机的**全部写入点必须埋日志**——「日志里 false→true 却找不到谁写的 false」说明有未埋点写入者，先穷举赋值路径再修，不要猜；②`rememberSaveable` 的恢复快照在「数据先少后多」的页面不可靠，进程级 holder + 非 saveable 构造（`remember { LazyGridState(...) }`）更可控；③新组装的 LazyGrid 前几帧会重置锚点，**任何首帧落位方案都必须逐帧重申或等稳定后落位**，单次 `scrollToItem` 会被冲掉；④`LazyGridState` 本版本构造参数名为 `firstVisibleItemIndex/firstVisibleItemScrollOffset`（无 `initial` 前缀），与 `rememberLazyGridState` 的参数名不同；⑤真机 logcat 主缓冲区可能很小（本机 256 KiB）且被系统日志灌满，抓日志前先 `logcat -G 4M` 扩容再清空，否则应用诊断日志几分钟内就被挤掉。

### 9.15 连续快速开关后「点漫画打不开」：phase 卡死 Visible + 返回键接管缺口

**现象**：连续快速打开/返回若干轮后，有概率出现异常，之后点击任何漫画都无反应，须重启进程恢复。

**日志实证**：最后一轮 `beginOpen → beginOpening → Visible(reason=Ready)` 之后再无任何流转——该轮返回**没有产生 `beginClose`**，路由被静默弹回书架而 phase 永久卡在 `Visible`。

**卡死机制（两层叠加）**：

1. **点击静默丢弃**：书架/历史两处点击入口都有 `if (phase == Idle)` 守卫，phase 卡非 Idle 时点击被静默丢掉（`beginOpen` 日志都没有）→ 只能重启；
2. **返回键接管缺口**：`openActive = phase == Opening`，Visible 阶段为 false——`ReaderScreen` 的兜底 `BackHandler(enabled = openActive)` 失效；此时返回全靠 `ReaderContent` 内部的无条件 BackHandler，而它**只在 ReaderContent 组合时注册**——快速开关中 session/错误态瞬间变化让 `ReaderContent` 被 `ReaderLoading` 顶替的瞬间，返回键没有任何 enabled 接管者 → 系统默认 popBackStack（静默，无日志）。

**帮凶**：`beginOpen` 是唯一没有 phase 守卫的流转函数——中途调用会无条件 `closeSession()` 清掉活会话（正是 ReaderContent 短暂卸载的源头之一）。

**修复（三重，任一环独立阻止卡死）**：

1. `beginOpen` 加守卫 `if (phase != Idle) return`（拒绝时打日志），与点击入口对齐；
2. **自愈兜底**：宿主 `LaunchedEffect(currentRoute, phase)`——路由在非 reader 页而 phase 仍在 Opening/Visible 时，600ms 复查后走 `beginClose("SelfHeal")` 动画化归位（Closing → 时间轴从当前进度反向 → markIdle；初版用 forceIdle 立即复位，后改为动画化，见变更记录「自愈误杀修正/自愈动画化」），新增 `ReaderOpenController.forceIdle()` 作为最后手段保留；
3. 返回键接管：`ReaderScreen` 新增 `backEnabled` 参数（宿主传「非 Closing 即接管」），兜底 BackHandler 改 `enabled = openActive || backEnabled`——Visible 阶段必有接管者。

**教训**：①「点击无反应」类问题先查入口守卫——守卫静默丢弃时不打日志，现象就是「点了没任何反应」，必须用日志确认 phase 当时是什么；②状态机的每个流转函数都要有 phase 守卫（本项目唯独 `beginOpen` 漏了），否则快速操作序列必然撕裂状态；③依赖「某 composable 存在时才注册的 BackHandler」兜底返回时，必须有一个路由级的最后防线，防止系统默认 pop 绕过状态机；④宿主持有的状态机要带自愈：任何「路由与状态机不一致」的组合（如 Visible+非 reader 路由）都应可检测并强制归位。

### 9.16 返回动画「飞向中间消失」：closing sourceRect 被书架瞬态布局污染

**现象**：返回动画小概率「丢目标」——飞回的容器跑向列表中间的错误位置并消失，一镜到底返回失效。

**根因**：关闭动画的飞回目标是**实时变化**的 `sourceRect`——`updateSourceRect` 在 Closing 期间接受书架卡片的实时回报（设计意图：旋转/阅读中列表变化后飞回新位置）。但返回时 Library 重组，网格首测量帧锚点回退 (0,0)（§9.14 已知行为，逐帧重申 ~2 帧后拉回），**这 2-3 帧里卡片上报的是「列表顶部布局」下的错误坐标**，`sourceRect` 被覆盖：被点卡片若在瞬态布局中不可见则不上报、`sourceRect` 保持上一轮循环的旧卡片位置（日志中出现过 (1009,927)/(53,1447) 等多个历史位置）——容器飞向旧位置/中间位置并消失；恢复落位后的正确回报来得太晚，动画已按错误目标飞完。

**修复**：`updateSourceRect` 加 Closing 时段门限——`beginClose` 记录起始时刻，**前 250ms 内忽略卡片回报**（瞬态窗口，恢复落位 ~200ms 完成），之后恢复接受。常规场景封面飞回 `beginOpen` 记录的被点卡片原位（恢复落位后逐像素对齐）；旋转/列表变化场景 250ms 后回报仍生效（设计意图保留）。

**教训**：①「动画目标实时回报」类设计必须考虑**宿主页面处于瞬态布局**的窗口——页面重组/恢复期间上报的坐标不可信；②给实时回报加时间门限（忽略瞬态窗口）是低成本高收益的通用手段；③诊断「飞错位置」类动画问题，先盯目标矩形的**更新序列**（谁在什么时刻覆盖了它），而不是动画本身。

### 9.17 返回收缩容器「被封面卡片遮挡」：采集层 GraphicsLayer 重放的合成序瑕疵

**现象**：Opening 中途返回的 abort 路径（返回按在进度 <0.98，navigate 未发生）小概率出现——收缩中的容器**被书架封面卡片遮挡**（卡片画在容器前面），容器「跳到所有封面后面」消失。

**排查**：两轮异常日志状态机完全干净（Preparing→Opening→beginClose→Closing→Idle，自愈/守卫/门限全部正确），排除状态机问题；全项目无 `zIndex`，兄弟绘制序按组合序固定——唯一动态绘制序机制 = **kyant `layerBackdrop` 的 GraphicsLayer 采集层**：书架内容挂 `layerBackdrop` 录入 RenderNode 供玻璃采样重放，快速连续开关时 Library 处于高速失效-重组窗口，**采集层重放绘制与本帧其它绘制的合成顺序在该实现下不稳定**，重放的书架内容（含封面卡）偶尔合成到宿主级 overlay Canvas 之后。

**修复**：`zIndex` 抬层，与应用层实现解耦——overlay 的容器 Canvas 与封面兜底 AsyncImage 加 `zIndex(1f)`（同层组合序保证封面在容器上），`GlassNoticeHost` 加 `zIndex(2f)`（通知保持最顶层）。zIndex 只影响宿主 Box 兄弟的合成序：无论 Scaffold 子树内部采集层重放怎么乱，**整个子树必定合成在 overlay 之下**。

**教训**：①宿主级悬浮层（过渡动画/overlay）与挂采集层的页面内容互为兄弟时，**必须显式 zIndex 声明层级**——不能依赖隐式组合序，采集层 GraphicsLayer 的重放合成序在高速失效场景下不可靠；②zIndex 只需加在宿主 Box 的直接子项上即可压住整个子树，不必逐个子项处理；③同一 z 层的多个兄弟（容器 Canvas/封面兜底/通知宿主）用不同 zIndex 值（1/1/2）维持原有相对层级。

### 9.18 reader 路由双重入栈：0.98 navigate 缺 launchSingleTop，条目累积致 phase 与路由错位

**现象族**（多个此前独立症状的最终触发源）：阅读中路由被静默弹回书架（自愈介入）→「闪回中间就失效」；同一本书快速开关若干轮后点击无反应须重启；阅读器以 fallback 形态滞留、返回无动画。

**日志实证**：异常轮（7671ce6e）`beginOpen → beginOpening` 后**全程无 `saved`**（0.98 navigate 未发生、Library 未弹出组合），但阅读器 UI 回调携带该书 bookId（路由条目 reader/7671ce6e 存在）→ 阅读器 UI 活在**栈里遗留的旧条目**上；`currentRoute` 读到 library → 自愈按设计动画化归位。

**根因**：0.98 的 navigate 无 `launchSingleTop`。navigate 后 `currentRoute` **异步更新**，窗口内 navigate effect 因其它 key（readerReady/contentBitmap 翻转）重启时，旧值 `route=Library` 仍满足条件、snapshotFlow 首采样即 `progress=1.0` → **立即再 navigate 一次 → 同一路由双重入栈**。快速开关同一本书时每次都叠一层 → 回退栈里 reader 条目累积，与 phase 状态机彻底错位；关闭只 pop 一个条目，多余条目滞留 → 后续所有错位症状。

**修复（一行）**：0.98 的 navigate 加 `launchSingleTop = true`（与 widget 深链路径写法对齐）——栈顶已是同名 reader 路由时 navigate 变 no-op，双重入栈竞态从机制上消失，回退栈永远只有一层 reader 条目。

**教训**：①`navigate` 后 `currentBackStackEntryAsState()` 异步更新，**任何「navigate 后靠 route 状态收敛」的效果重启窗口都可能重复触发 navigate**——路由跳转一律带 `launchSingleTop`（或等价幂等保护），除非语义上明确要叠加；②「无 saved/dispose 日志但页面 UI 活跃」= 页面活在遗留路由条目上，是回退栈脏数据的标准指纹；③多轮独立症状（闪现/失效/须重启）合并排查时，找**共同触发源**（本例：条目累积）比逐个修症状高效。

### 9.19 「动画在所有封面后面」终案：采集层 GraphicsLayer 录制/重放失步（屏幕录像定位）

**现象**：快速连续开关同一本书时，一镜到底动画整体不可见——屏幕全程停留在书架旧画面（用户描述「动画跳到所有封面后面去了」），zIndex 抬层无效。

**定位手段（屏幕录像 + 时间戳对齐）**：`adb shell screenrecord` + mp4 `creation_time` 元数据与 logcat 时间戳对齐，ffmpeg 按帧提取异常轮。**决定性证据**：十连快速开关（每轮 ~1s，logcat 状态机完整流转、路由正常 push/pop、`saved` 正常）的逐帧画面里，**阅读器全屏黑页与一镜到底容器一帧都没出现**——屏幕持续显示书架的陈旧画面。

**根因**：全项目唯一非常规合成机制 = kyant `layerBackdrop`（Scaffold 内容挂 `Modifier.layerBackdrop(backdrop)` 录入 GraphicsLayer 供玻璃 chrome 采样）。快速连续开关时 Library 处于高速失效-重组窗口，**采集层的录制/重放失步，陈旧书架图层被持续合成在 live 树之上**——阅读器与动画容器真实存在但被压在下面。此机制同时解释：zIndex(1f) 无效（遮挡物不在兄弟 z 序内）、低概率（仅高速失效时失步）、此前「闪回中间/失效/须重启」的部分同源性。

**修复**：一镜到底激活期间（`phase != Idle`）跳过 Scaffold 内容的 `.layerBackdrop(backdrop)`（`.then` 条件挂载）——此时 chrome 已隐藏或正在淡出（chromeVisible=false），采集层无人采样，摘掉零损失；Idle 后重新挂载恢复录制。内容回归正常实时绘制，阅读器/容器立即上屏。

**教训**：①**纯渲染类异常（日志干净但画面不对）必须上屏幕录像**——logcat 只能证明状态机正确，不能证明像素正确；②录屏 + mp4 `creation_time` 与 logcat 时间戳对齐 + ffmpeg 逐帧网格，是定位渲染失步的标准手段；③「页面内容挂在采集层 GraphicsLayer 上」的应用，在高速失效-重组场景下可能出现录制/重放失步——激活态动态摘挂采集层修饰符（无人采样时摘掉零损失）是低成本兜底；④宿主级悬浮动画与采集层内容互斥期间，优先让悬浮层走正常绘制路径。

### 9.20 返回动画「切换到封面瞬间」掉帧：封面位图 GPU 纹理懒上传

**现象**：所有速度档、与滚动位置无关，返回动画在「内容切换到封面」的一瞬间闪一下/掉帧。

**定位（gfxinfo 指纹）**：`Number Slow bitmap uploads: 4` 与测试的返回次数一致；`Slow UI thread` 高而 GPU 百分位极小——CPU 侧位图上传签名。**机制**：一镜到底打开阶段不绘制封面（设计如此），`coverBitmap` 全程未被绘制；返回 Closing 的交叉淡化（pageAlpha↓ / coverAlpha↑）里封面**第一次被绘制**——Compose/GPU 位图纹理懒上传，首绘即上传（卡面尺寸 ~1.1MB，10-50ms）→ 卡掉 1-5 帧。与时长档位、滚动位置均无关。

**修复**：overlay draw 块在 **Opening 期间以 alpha 0.01 预绘封面一帧**（隐藏在页面内容之下不可见）——纹理上传成本落在打开动画内，返回交叉淡化命中已就绪纹理，闪现消失。

**教训**：①**交叉淡化里「第一次出现」的位图必带懒上传帧尖峰**——预热手段：在上一段动画里以近零 alpha 预绘同一张位图；②`gfxinfo` 的 `Slow bitmap uploads` 计数是这类闪帧的直接指纹（次数≈异常次数）；③GPU 百分位小 + UI 线程慢 = 位图上传/布局类问题，与合成器无关。

### 9.21 返回动画整体掉帧（M5 回归）：全书分格预检把整页解码放在主线程

**现象**：一镜到底返回动画明显掉帧，所有速度档、与滚动位置无关、关掉动画也卡。用户线索「M5（智能分格）之后才出现」。

**对照实验（关键方法）**：`settings put global animator_duration_scale 0` 旁路一镜到底后重测——卡顿依旧（janky 20.18%、90th=27ms），**证明成本不在 overlay 本身，而在阅读器→书架的切换链路**；正式版对照：有动画 4.49% / 无动画 20.18%（分母小、绝对值接近），两路都卡 → 锁定在切换时仍在跑的后台工作。

**根因（M5-D 回归）**：`detectPanelLayout`（ReaderScreen.kt）里 `loader.load(pageIndex, ...)` **在调用方上下文执行**——而调用方是全书分格预检循环（`LaunchedEffect` 默认主线程）：

```kotlin
LaunchedEffect(book.id, ...) {
    for (page in 0 until count) { detectPanelLayout(...) }   // 每页一次主线程整页解码
}
// detectPanelLayout 内：
val bitmap = loader.load(pageIndex, ...)                  // ← 解码留在主线程（50-100ms/页）
val layout = withContext(Dispatchers.Default) { analyze(bitmap) }   // 只有分析切了线程
```

每次打开阅读器即启动全书逐页预检，主线程被一页接一页的整页解码堵住；返回书架时循环正卡在解码里 → 动画帧被堵 → 掉帧。解码在主线程还使循环无法在暂停点取消，阅读器销毁后仍跑完当前页。

**修复**：`loader.load(...)` 包进 `withContext(Dispatchers.IO)`（同时成为取消检查点）+ 预检循环每页间 `if (!isActive) return@LaunchedEffect` 即时响应取消。

**教训**：①`suspend` 函数不等于「非阻塞」——**在 `LaunchedEffect`（主线程）里调用的 suspend 函数，内部未显式 `withContext` 的部分都在主线程执行**；逐页/批量的后台工作必须把 IO/解码整段切走；②「某里程碑后出现的掉帧」优先 diff 该里程碑新增的后台循环/预检/缓存写入路径；③对照实验（系统动画缩放 = 0 旁路动画）是区分「动画本体开销」与「底层页面切换开销」的零构建手段。

### 9.22 返回动画「闪一下」：prefs 异步首帧导致 viewMode 结构翻转

**现象**：M5 掉帧修复后浮现——返回动画下书架瞬态跳动一下（此前被掉帧掩盖）。

**日志实证**：返回后网格首帧 `(0,0)`，57ms 后被逐帧重申拉回 `(4,620)`；状态机全程 `true->true` 无翻转。**根因**：`prefs`（DataStore）首次发射是异步的（几十 ms），`collectAsStateWithLifecycle(initialValue = null)` 期间 `prefs=null` → `viewMode` 退回默认「书架视图」(folder)，而用户实际是「平铺」(flat，设备设置实证 `library_view=flat`)——prefs 到达后网格结构整体翻转、item 数变化 → 锚点被夹回 (0,0) → 恢复链路 57ms 后拉回，这 57ms 里容器下方的书架是错误结构，缩小时露出的边缘即「闪一下」。**该翻转同时是此前 resetKey/viewMode 震荡（展开→折叠误杀）的同源诱因。**

**修复**：`SettingsRepository` 增加内存缓存快照（`@Volatile lastKnown`，`preferences` 流上 `onEach` 更新，`cachedPreferences()` 同步读取）；`LibraryScreen`（及 `MainActivity` 主题）的 `collectAsStateWithLifecycle` 用缓存快照做 `initialValue`——首帧 viewMode 即为实际值，结构零翻转。冷启动首次进入无缓存时行为同旧（仅一次）。

**教训**：①**视图模式/主题这类决定布局结构的设置，必须能同步取到首帧值**——DataStore 首发射是异步的，`initialValue=null` 会让结构先落默认再翻转，产生布局跳动与锚点夹紧；内存缓存快照是低成本的正解；②「掉帧修好后闪一下」= 旧问题显影，不是新回归——先查日志里的瞬态锚点/结构变化，再怀疑新改动；③排查设备具体配置（`run-as ... cat dataStore` 的 pb 里 grep）比追问用户更快：`library_view=flat` 一锤定音。

### 9.23 竖屏打开 → 切横屏 → 返回：容器「不知道该返回哪」（三层修复：stale 检测 / settled 回报 / 跨方向恢复）

**现象**：竖屏打开书，阅读中切横屏（或横屏转回竖屏）再按返回，返回动画飞向错误位置/屏幕外，漫画与小说都复现。

**根因（三层叠加）**：

1. **sourceRect 整个 Visible 阶段冻结**。`updateSourceRect` 只在 Closing 接受，且 §9.16 的 250ms 时间门限挡住恢复期回报。旋转后书架从未以新方向布局过（NavHost 栈底不组合），返回瞬间才第一次重建；可信的新方向坐标回报到达时（数据生长 ~120ms + 逐帧重申 + 门限 250ms），动画（260~360ms）已经按旧坐标飞完 `markIdle`。
2. **横屏屏幕上竖屏坐标完全失义**：overlay 的 draw 纯函数 `lerp(sourceRect → 全屏, p)` 直读旧坐标——竖屏 y 可达 2400px，横屏高度只有 1080px，目标点在屏幕外/角落。
3. **恢复的滚动位置是旧方向语义**：`LibraryGridScroll` 存 index/offset；跨方向时 offset 的像素语义失效；且被点卡片若不在视口内（`updateSourceRect` 有 bookId 过滤）就永远收不到回报。

正常竖屏直返之所以一直是好的：打开时记录的 sourceRect 与返回恢复后的卡片位置天然一致（同方向、同布局、同滚动位置），门限挡掉的回报根本无关紧要——旋转第一次打破了这个一致性。`targetRect` 无此问题（Reader 旋转时持续上报，返回时已是当前方向的正确值）。

**修复（三层）**：

- **A 层（controller）**：`beginClose` 由宿主传入当前根尺寸，与 `beginOpen` 记录值对比 → 不同则 `sourceRectStale=true` 并拉起 `closingHold` 起飞闸；timeline 在 Closing 且 hold 时 progress 停在全屏（容器与 Reader 末帧同构、盖住书架以新方向重建的过程），`snapshotFlow` 等闸释放后再反向；宿主 600ms 超时 `releaseClosingHold()` 兜底（旧坐标飞完，宁可错不卡死）。
- **B 层（页面侧 settled 信号替代时间门限）**：书架 `gridSettled` / 历史页 `listSettled`——网格/列表落位稳定（恢复 effect 完成 / item 数连续两帧稳定）前卡片回报带 `settled=false` 被 controller 忽略，首个 settled 回报生效并解除起飞闸。**关键竞态补丁**：`onGloballyPositioned` 只在位置变化时回调，落位后不再有回调——settled 在最后一次位置回调之后才置位的话 controller 永远收不到回报，所以 BookCell/历史卡在 settled 翻 true 时用最后已知位置**补发一次**回报。
- **C 层（跨方向恢复）**：`LibraryGridScroll` 新增 `landscape`（离开时方向，onDispose 写入）与 `anchorBookId`（宿主 onOpenBook 写入）。跨方向恢复时 index 是线性序号仍然有效、offset 归零；锚点优先——flat 视图且书架根时把视口定位到最近打开的书（返回动画的飞回目标），保证目标卡在视口内能回报；查不到退回原 index。

**教训**：①「动画目标实时回报」类设计必须考虑宿主页面处于**瞬态布局**的窗口，时间门限只是过渡手段——恢复是否完成应由页面侧的稳定信号判定，而不是与动画时长赛跑；②旋转场景下「打开时记录的坐标」与「返回时卡片实际位置」的一致性被打破，任何缓存矩形都要带方向/尺寸戳做失效检测；③`onGloballyPositioned` 是"变化驱动"回调，**主动置位的稳定信号必须配套一次性补发**，否则等待方永远等不到事件；④横竖屏切换会让进程级滚动位置语义漂移，恢复逻辑要有跨方向分支（线性 index 保留、像素 offset 归零 + 内容锚点校准）。

### 9.24 第一轮修复后仍不稳定：模拟器逐场景验收揪出五个残留真凶（2026-11-16 第二轮）

第一轮三层修复装机后用户真机反馈「有时候回去位置不对，有时曲线很夸张」。用模拟器（dsh_test，1080×2400）逐场景录屏+logcat 验收，定位并修复五个独立缺陷：

1. **自愈误杀 Opening（「曲线夸张」最可能真凶）**：自愈判据是「phase=Opening 且 600ms 后 route 仍非 reader」——但 Opening 期间 route 本就停在 library/history（0.98 才 navigate），**动画没播完时这不是卡死**。慢机/帧冻结下 animateTo 推进晚于 600ms（模拟器实测 progress 冻结 0 达 1.8s），自愈把正常打开的飞行容器反向拉回——用户看到容器飞一半突然改道。修复：Opening 分支先等 `progress >= 0.98`（最多再等 2s，超时才判定真死），等到后给 route 状态 150ms 传播缓冲再复查；Visible（静默 pop）维持 600ms 复查。
2. **`landscape` 保存了陈旧方向**：`DisposableEffect(Unit)` 的 onDispose 闭包捕获**首次组合**的 `LocalConfiguration`——旋转重组不重装 effect（key=Unit），横屏打开却存了 `landscape=false`，下次进入误判 `cross=true` 走锚点路径强滚。修复：方向改用 `gridState.layoutInfo.viewportSize` 宽高判断（onDispose 时实时值）。
3. **恢复重申循环在同行 item 上死循环**：Adaptive 列数下目标 item 可能与行首同行，`scrollToItem` 按行落位、`firstVisibleItemIndex` 停在行首（实测横屏一排 5 本时 scrollToItem(4) 落 (1,0)，视觉已正确）——`curIndex == index` 精确比较永远不满足，白耗 40 帧拖慢 settled。修复：落位判定改「目标 item 在 visibleItemsInfo 内」。
4. **起飞闸超时早于正常回报**：实测横屏恢复落位+settled 回报 ~700-780ms，600ms 超时先触发、动画前段按旧坐标飞再改道。修复：`CLOSING_SOURCE_WAIT_MS` 600→800。
5. **历史页目标卡滚出视口后零回报**（「位置不对」）：历史页走 NavHost saveable 恢复，横竖布局差异让目标卡漂出视口——卡片不组合就永不回报，超时按旧坐标飞。修复：settled 后锚点滚动把目标卡带回视口（item 序号 = stats 卡 0 + entryIndex+1）。**关键坑**：目标卡 `visible=true` 时 LazyColumn 可能没有新布局 pass，`onGloballyPositioned` 一次都不触发（实测零回调）——锚点滚动改**无条件执行**（同位置 scrollToItem 也走 relayout 强制触发回调），卡片才上报当前位置。

**验收矩阵（模拟器全通过，日志+截图证据）**：竖开竖返（零改道、坐标逐像素一致）；竖开横返（rotated=true → 起飞闸 hold → 瞬态回报被挡 → 锚点校准 → settled 回报横屏坐标 → 动画飞对，截图见容器对准目标卡当前位置）；横开横返（landscape 修复后不再误判 cross）；横开竖返（反向路径对称闭环）；历史页竖开横返（锚点滚动+回报，返回后停在目标卡处）。环境注意：模拟器过载时帧循环可慢至 ~1fps，一镜到底这类帧驱动动画会失真（progress 冻结、跳变），**帧级观感验收必须真机**，模拟器适合日志级状态机/矩形链路验证。

**教训**：①「600ms 延时 + 单次复查」的自愈判据在慢机/卡顿场景必然误杀——**「路由没切」的前提是「动画已完成」**，状态机自愈的触发条件必须包含其驱动者（timeline）的真实进度；②`DisposableEffect(Unit)` 的 onDispose 闭包捕获首帧 CompositionLocal/环境值，旋转重组不重装，**一切随重组变化的环境读取要用实时源**（如 layoutInfo.viewportSize）；③「目标 item 可见却零 gp 回调」= LazyList 没有 relayout pass——**恢复后的落位验证要区分「数据可见」与「布局发生」**，必要时用 scrollToItem 同位置强制 relayout；④多场景验收矩阵（竖横四向 × 书架/历史两入口）比单场景重复测更易暴露不对称缺陷。

### 9.25 一级其它组合 / 二级页仍回顶 + 状态栏闪：恢复体系只挂在一级网格上（2026-11-22）

**现象**：一镜到底返回后，①「全部-平铺」已修，但书架 chips 的「漫画/全部」其它组合、以及书夹/系列/智能书夹点进去的**二级页**仍会「自动回顶」；②这些页面返回时状态栏会「消失又出现」，与进书前的显隐不一致（要求：原本没隐藏回去就没隐藏，原本隐藏回去就隐藏）。

**根因（四处，同一族）**：

1. **二级页网格是空构造、无保存点**：`val targetGridState = remember(t) { LazyGridState() }` —— 进阅读器时 Library 被 NavHost 卸载，返回重建即 (0,0)；`onDispose` 只保存了一级的 `gridStates`。
2. **恢复 effect 只作用于一级网格**：二级页返回时它 `scrollToItem` 一个**没组合**的网格（无效/挂起），而 `gridSettled = true` 写在它末尾 → settled 延后 ~1.28s 甚至永不置位，超出宿主 800ms 起飞闸，卡片回报一直被忽略（返回动画按旧坐标飞）。
3. **`headerState` 的网格真源写死一级**：二级页时 `canScrollForward/Backward` 恒 false → 命中「短内容不折叠」守卫，二级页上滑**根本不折叠**头部；`atTop` 读未组合的一级网格（恒在顶部）→ `showActions` 恒真，把方向显隐的「隐藏」压掉 → 返回时状态栏被强制 `show()`，与进书前的隐藏态打架。
4. **恢复目标组合靠推导 + 落位判定过松**：保存用 `currentViewMode`（离开时实时值），恢复却用 `initialViewMode`（进书架时 prefs 快照）+ `LibraryUiState.typeFilter`；两者一旦不同源（prefs 首帧 null / 书架内切过视图）就作用在错误组合上。落位判定 `visibleItemsInfo.any { it.index == index }` 在目标靠近顶部（返回时数据从顶部渲染）时常真 → 逐帧重申被立即 break，首测量帧的 (0,0) 不被纠正。

**修复**：

- **活跃网格单点**（`LibraryScreen`）：`detailStates: HashMap<targetKey, LazyGridState>`（普通 HashMap，退场页按旧 t 仍取旧实例）+ `activeGridState = 二级 ?: 一级组合网格`；`headerState` 的 `gridState` 绑定它，`resetKey` 加 `targetKey`（进出二级页头部滑回展开）。
- **恢复改成事实驱动**：`LibraryGridScroll` 新增 `viewMode/typeFilter`（离开时的组合）与 `extentFraction`（折叠量比例）；新增 `LibraryDetailScroll { key, index, offset }`；`onDispose` 一并落值；恢复 effect 按「当前真正显示的网格」调用抽出的 `restoreGridPosition()`。
- **落位判定改位置比较**：`firstVisibleItemIndex/offset == 目标` 或 `abs(item.offset.y + offset) <= 2`；并加 `withTimeoutOrNull(3000)` 兜底（网格未 attach 时 `scrollToItem` 会挂起，不能把 settled 卡死）。
- **状态栏严格保持**：`rememberGlassHeaderState` 新增 `statusBarHold`（书架传 `!gridSettled`）——Closing 之后继续挂起状态栏控制与 `LibraryStatusBar.visible` 写入，直到恢复落位；`atTop` 加「条目数 > 0」守卫（未组合/空数据不算触顶）。
- **折叠量按比例恢复**：布尔只能表达「折满/未折满」，部分折叠返回时会被当成展开、顶部让位瞬间长出来（整页下跳）。
- **二级页标题行并入头部**：`headerContentHeight` 在二级页 = 108 + 56dp（返回钮 / 名称 / 数量 + 8 间距；排序已统一为全 App 全局档，入口只在一级标题行与平板侧栏），标题行渲染在 header 层并吃同一个 `headerOffsetPx` → 与书架标题/chips 刚性同移，折满（extent = H）时整行出屏、网格顶到屏幕最上；二级页上滑折叠至此成立（用户要求的「连带二级页标题一起折叠」）。

**代价/边界**：进出二级页时 `expandedTop` 变化 ±56dp（`extentPx` 读取处已夹到 `[0, H]`）；二级页标题行不参与一级↔二级的内容滑入转场（属于 header，进页即出现）；`restoreGridPosition` 的数据稳定等待仍是最长 40 帧。

**相关文件**：`LibraryScreen.kt` / `GlassImmersiveHeader.kt` / `ScrollToTop.kt`（备份 `backups/library-detail-header_20261122/`）。

### 9.26 小说返回「标题跳到状态栏位置再回落」：冻结值取到了 inset 动画中间值 + 小说/漫画返回链路不统一（2026-11-22）

**现象**：漫画一切正常；**小说**从任何页面（一级 / 二级页 / 系列）打开再返回，标题先**上移约一个状态栏高度**、随后回落。另有小说返回「踩顶栏 / 退出堆叠」（收缩容器外透出仍在挂载的阅读器正文/顶栏）。

**取证（`InkvolOpen` 日志实证，一次复现定案）**：

```text
diag header init sbTop=40.0 live=40.0 remembered=40.0 ... frozen=null    ← 第一次返回正常
diag header init sbTop=0.38 live=40.0 remembered=40.0 ... frozen=0.38    ← 之后每次都塌
diag header init sbTop=0.76 live=40.0 remembered=40.0 ... frozen=0.76
```

**根因一（跳动）**：`savedStatusBarTop` 用**实时** `WindowInsets.statusBars` 记录。小说打开时宿主（Opening / 路由 effect）与阅读器屏都会 hide 系统栏，0→40 的过渡中间值（0.38 / 0.76dp）在 Library 卸载前被写进 `rememberSaveable`，下次返回就被当成「进书前状态栏高度」冻结 → `statusBarTop≈0` → 标题上移一个状态栏高度；Closing 结束冻结解除 → 回落到 40dp。

**根因二（堆叠）**：小说与漫画的返回链路不同 —— ①小说 `closeReaderOpen` 不恢复系统栏，延迟到 `phase == Idle`（`pendingNovelBarRestore`），漫画立即恢复；②小说垫层 `novelReaderMounted` 用 `currentRoute` 判断阅读器是否还挂着，而路由状态滞后真实回退栈 2~3 帧（§9.18），垫层撤除与阅读器卸载错位 → 退栈那几帧真实阅读器正文/顶栏透出叠在书架上。

**修复（漫画 / 小说统一为同一套时序）**：

1. **冻结值来源改 `statusBarsIgnoringVisibility`**（与显隐无关、恒等于显示态高度），只记录 `> 0` 的稳定值；`frozenStatusBarTop` 加 `> 1dp` 阈值挡住历史残留的 0.38。
2. **返回恢复系统栏统一**：删除 `pendingNovelBarRestore` 与 Idle 恢复 effect，`closeReaderOpen` 一律立即按 `LibraryStatusBar.visible` 恢复（可见→`show(systemBars)`，隐藏→只 `show(navigationBars)`）。inset 回归动画落在 Closing 期间，由冻结让位吸收，不再出现「动画放完状态栏才冒出」。
3. **垫层判据统一**：新增进程级 `ReaderSurfaceAlive`（两个阅读器屏 `DisposableEffect` 引用计数），垫层 = `isNovel && phase == Closing && ReaderSurfaceAlive.alive`，彻底摆脱异步 `currentRoute`。
4. **状态栏高度记忆化兜底**：`LibraryStatusBar.statusBarTopPx` 由玻璃头在 insets 有效时持续写入，首帧 `statusBarsIgnoringVisibility` 报 0 时用它兜底（设备真无状态栏时记忆值也是 0，无副作用）。

### 9.27 小说交接后「先显示章节、再跳到具体内容」：首帧 pager 从第 0 页起步 + 就绪上报抢跑（2026-11-23）

**现象**：打开过渡本身已经平滑（封面 → 正文交叉），但**交接完成后**第一眼是先看到章首页（第 0 页），然后跳到实际阅读位置。

**根因（两处叠加）**：

1. `rememberPagerState(initialPage = 0)` —— Reader 首帧必是第 0 页；真正的定位在首帧之后：

   ```kotlin
   LaunchedEffect(pages, spreads, useDouble) {
       ...
       settlePage(idx.coerceAtLeast(0))   // 首帧后才执行
   ```

   而一镜到底 overlay 交接的快照是**目标页**（按 `pendingRestoreOffset` 渲染）。于是画面是：`overlay 目标页` → 撤 overlay → `Reader 第 0 页` → 下一帧跳目标页。

2. `onReaderReady` 不等锚定：

   ```kotlin
   LaunchedEffect(loading, paginating, pages) {
       if (!loading && !paginating) onReaderReady()
   ```

   宿主拿到 ready 才 `markVisible` 撤 overlay，抢在锚定前上报 → 跳页明着演出来。

**修复**：

- `initialPageIndex`：用 `activeSession.pendingRestoreOffset` 在 `activeSession.firstPagination.pages` 上求页号（双页按 spread 求），`rememberPagerState(initialPage = initialPageIndex)`；`restore < 0` 或半截快排页覆盖不到时回落 0，由原锚定 effect 兜底纠正；
- `onReaderReady` 改为等 `anchoredOnce`（`withTimeoutOrNull(300)` 兜底，避免极端情况下 overlay 永久挂住）。

**效果**：交接帧与 Reader 首帧都是目标页，跳页（若还有）发生在 overlay 之下，不可见。

**相关文件**：`NovelReaderScreen.kt`。

### 9.28 「先跳第X章（中间只有一行字）再跳正文」：分页器早停截出单行残页（2026-11-23）

**现象**：§9.27 修好「首帧落错页」之后，EPUB / MOBI 打开仍会先出现「屏幕中间一行字」，随后才出现整页正文；TXT 不受影响。

**根因（`NovelTextPager.paginate`）**：`stopAfterCharOffset` 的早停写在「第一片刚覆盖目标偏移」处就 `break`：

```kotlin
                appendSlice(...)
                if (stopAfterCharOffset >= 0 && currentPageEnd > stopAfterCharOffset) {
                    stopped = true
                    break
                }
```

→ 目标页只剩第一行 / 第一段。渲染侧把页内余量平分到上下（`remPx / 2`），于是这一行正好落在**屏幕中间**。预打开快照与 Reader 首屏都用这张残页，随后整章分页把同页填满，看上去就是「一行字 → 整页正文」。EPUB/MOBI 章首有独立标题块、进度偏移常落在其中，所以必现；TXT 的偏移落在正文段内（段本身已多行），残页不明显。

**修复**：

1. 分页器：覆盖目标偏移只做标记 `targetReached`，继续把当前页填满，等 `flushPage()` 刷出（页已满 / 段落跨页）后再停；同步去掉按块数预截断（`blockLimit = blocks.size`），否则填不满目标页。
2. 预打开（`ReaderOpenViewModel.preloadNovel`）：章首（`anchorChar <= 0`）不再按偏移截断，改为按页数排完整首屏（`maxPages` 的停页发生在 `flushPage()` 之后，页是完整的）。

**效果**：预打开快照 = Reader 首屏 = 整章分页的同一页，逐像素一致；不再出现「中间一行字」的残页。

**相关文件**：`NovelTextPager.kt` / `ReaderOpenViewModel.kt` / `NovelReaderScreen.kt`。

## 12. 小说阅读器接入（2026-11-16）

小说阅读器复用同一套状态机、时间轴、overlay 与路由时序，差异集中在飞行内容与返回快照。

### 13.1 预打开数据

- 点击后先解码封面并 `attachNovelCoverOnly()`，**封面先行起飞**，避免等待正文快照造成空屏。

- 系统栏改为 `Opening` 阶段才隐藏，快照准备期间不再提前改变 inset。
- 路由切换与漫画统一为 0.98 / 0.995。

### 13.3 返回

- 返回前用当前阅读页快照（`updateNovelContent()`）作为收缩内容。
- `ReaderOpenOverlay` 新增 `novelReaderMounted`：小说路由尚未退栈时，先铺满不透明正文底色，避免容器外透出真实阅读器正文。

### 13.4 交接细节

- 快照与真实正文共用同一 `TextStyle`，保证视觉一致性。
- 小说打开首帧隐藏顶/底栏，交接后由用户单击唤出 chrome。
