# Inkvol 发版规范

> 适用范围：`main` 分支、Git tag、GitHub Release、以及后续所有商店渠道。
> 单一真源：版本号在 `gradle.properties`，构建在 `scripts/build-release.ps1`，检查在 `scripts/check-release-safety.ps1`，更新记录在 `CHANGELOG.md`。
> 最后更新：2026-11-25。

**核心原则：发版前必须跑安全自检脚本，任何 `[FAIL]` 都必须清零；不靠记忆，靠脚本 + 清单。**

---

## 1. 版本号

| 项 | 规则 |
|---|---|
| 命名 | 语义化版本 `MAJOR.MINOR.PATCH` |
| versionName | `1.0.0`、`1.0.1`、`1.1.0` |
| versionCode | `MAJOR*10000 + MINOR*100 + PATCH`，1.0.0 → `10000` |
| 唯一来源 | `gradle.properties` 的 `INKVOL_VERSION_CODE` / `INKVOL_VERSION_NAME` |
| 单调性 | 新版本 versionCode **必须大于**上一 tag，脚本会校验 |
| 禁止 | 复用旧版本号、覆盖已发布 tag、在代码里硬编码版本号 |

**何时升位**

- PATCH：修 bug、文案、兼容性，不改数据结构
- MINOR：新增功能或格式支持，向后兼容
- MAJOR：数据结构 / 同步协议 / 行为不兼容

---

## 2. 分支与 tag

- `main` 始终可发布；未验证的大改走分支
- 分支：`feat/<简述>`、`fix/<简述>`、`hotfix/<版本号>`
- tag：附注 tag，`vX.Y.Z`，**只打一次**
- 已推送的 tag **不移动、不删除、不重打**；打错就发下一个版本
- 发布后建议开启仓库的「Immutable releases」，防止资产被替换

---

## 3. 提交信息

```
feat: 支持 7z/CB7 内嵌图片索引
fix: 修复 PDF 关闭后读取页数崩溃
docs: 补充发版规范
chore: 清理未使用依赖
release: 1.0.1
```

正文写“为什么 / 影响面 / 自测方式”；一次提交只做一件事。

---

## 4. 构建环境与供应链

### 4.1 当前基线（1.0.0 实测）

| 项 | 值 |
|---|---|
| JDK | 17.0.20+8 |
| Gradle | 9.6.0（wrapper） |
| AGP | 9.4.1 |
| Kotlin | 2.3.21 |
| compileSdk / targetSdk | 37 / 37 |
| minSdk | 26 |
| build-tools | 34.0.0 |

每次发版把这份基线写进 `dist/release/vX.Y.Z/SIGNING.txt`，便于复现与排查“只有我这台机器能构建”的问题。

### 4.2 已知风险（待处理）

| 风险 | 现状 | 处理 |
|---|---|---|
| wrapper 校验和 | 已写入官方 `distributionSha256Sum`（`bbaeb2fe…529a01`） | 镜像文件被替换时构建直接失败 |
| wrapper 走第三方镜像 | `mirrors.cloud.tencent.com` | 已实测镜像文件 SHA-256 与官方一致；升级 Gradle 时需重新核对官方值 |
| 无 CI | 构建只在本地 | 可选：GitHub Actions 只做“可复现校验”（不签名），或至少记录环境基线 |
| 依赖完整性 | 未启用 Gradle verification metadata | 可选进阶项，首次生成成本较高 |

### 4.3 依赖规则

- 禁止动态版本（`+`、`latest.release`、`[1.0,2.0)`）；当前 `libs.versions.toml` 已全部锁定
- 新增依赖先看：许可证、维护状态、是否引入原生库、是否申请新权限
- 升级 AGP/Kotlin/Gradle 后必须重跑完整回归

### 4.4 构建机卫生

- 用专用账户构建，开启磁盘加密
- 构建前工作区干净（`git status` 为空）
- 不安装来源不明的 IDE 插件/脚本
- 密钥只放在这台机器，不通过聊天工具传口令

## 5. 发版流程

```powershell
# 0) 安全自检（可先跑，缺失项会列出）
powershell -ExecutionPolicy Bypass -File scripts\check-release-safety.ps1 -SkipRemote

# 1) 改版本号：gradle.properties 的 INKVOL_VERSION_CODE / INKVOL_VERSION_NAME
# 2) 更新 CHANGELOG.md

# 3) 构建（APK + AAB + mapping 私有归档 + SHA256）
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1

# 4) 再跑一次自检（这次含远端）
powershell -ExecutionPolicy Bypass -File scripts\check-release-safety.ps1

# 5) 回归（见第 11 节）

# 6) 显式暂存（禁止 git add -A / git add .）
git add app docs scripts .github README.md CHANGELOG.md gradle.properties `
        build.gradle.kts settings.gradle.kts .gitignore
git status --short          # 确认没有密钥/产物/书籍
git commit -m "release: 1.0.1"
git tag -a v1.0.1 -m "Inkvol 1.0.1"
git push origin main
git push origin v1.0.1

# 7) 创建 Release（资产见 6.3）
gh release create v1.0.1 --title "Inkvol 1.0.1" --notes-file dist\release\v1.0.1\RELEASE_NOTES.md --latest `
   dist\release\v1.0.1\Inkvol-1.0.1.apk `
   dist\release\v1.0.1\SHA256SUMS.txt `
   dist\release\v1.0.1\SIGNING.txt
```

Release 正文统一包含：版本号、变更摘要、安装说明（含“旧测试包需卸载”）、SHA256、签名指纹、源码 tag 链接、已知限制、反馈方式。

## 6. 安全边界：什么能上传，什么不能

### 6.1 可以进入公开仓库

| 内容 | 说明 |
|---|---|
| 源码、资源、gradle 配置 | 不含口令 |
| `LICENSE` / `assets/legal/gpl-3.0.txt` | GPL 分发要求 |
| `CHANGELOG.md`、`README.md`、`docs/*.md` | 内部交接 `docs/handoff*.md` 除外 |
| `scripts/*.ps1` `scripts/*.py` | 必须 ASCII、不含密钥与本机绝对路径 |
| `.github/` 模板、`SECURITY.md` | 反馈与安全渠道 |
| 原创图标源与生成脚本 | 无版权争议 |

### 6.2 严禁进入公开仓库（也不要贴到 Issue/PR）

| 内容 | 原因 |
|---|---|
| `keystore/`、`keystore.properties`、`*.jks`、`*.keystore`、`*.p12`、`*.pem`、`*.key` | 签名私钥泄露 = 可冒充发布更新 |
| `local.properties` | 含本机 SDK 路径 |
| `dist/`、`build/`、`app/build/`、`.gradle/` | 产物与缓存；`mapping.txt` 会降低逆向门槛 |
| `logs/`、`*.log`、`build_log*.txt`、`crash-*.txt` | 可能含书名、路径、设备标识 |
| `backups/`、`backup/`、`*.db`、`inkvol-backup*.json` | 真实书库、进度、偏好（可能含同步服务器地址） |
| `test_samples/`、真实书籍/漫画、含版权内容的截图 | 版权与隐私 |
| `tools/` | 本地工具、含本机路径的脚本、第三方源码快照 |
| WebDAV 账号/应用密码、GitHub token、`gh` 凭据 | 直接盗号/盗数据 |
| 带个人路径的截图、录屏 | 暴露用户名与目录结构 |

### 6.3 Release 资产怎么选

| 资产 | 公开上传 | 说明 |
|---|---|---|
| `Inkvol-X.Y.Z.apk` | ✅ 必须 | 用户安装 |
| `SHA256SUMS.txt` | ✅ | 只列公开资产，否则 `sha256sum -c` 会报缺失 |
| `SIGNING.txt`（证书指纹） | ✅ | 用户核对，防山寨包 |
| `Inkvol-X.Y.Z.aab` | ❌ 不必 | 仅供 Play，公开无收益 |
| `mapping-X.Y.Z.txt` | ❌ 禁止 | 混淆映射只做私有归档 |
| 源码 zip | ❌ 不必 | 由同版本 tag 提供，满足 GPL |

> 历史：`v1.0.0` 曾误传 mapping，已于 2026-11-25 删除；清理命令 `gh release delete-asset <tag> <文件名>`。

### 6.4 日志与备份脱敏

- 崩溃日志可能包含书名、文件路径、设备信息；贴到 Issue 前删掉书名与个人路径
- 备份 JSON 含书库索引、进度、偏好，**任何情况下都不公开**
- WebDAV 凭据在应用内用 Keystore 加密，但备份文件仍按敏感文件处理

### 6.5 密钥保管

- `keystore/inkvol-release.jks` 与口令**分开存放**，各两份（一份离线）
- 换机/重装后先用旧包验签，确认密钥可读再发版
- 接 CI 时：密钥以 base64 存 GitHub Secrets，构建时临时落盘、任务结束删除；不得写入仓库或日志

## 7. 构建配置安全基线

| 项 | 现状 | 要求 |
|---|---|---|
| `debuggable` | false | 脚本会检查，出现即阻断 |
| `usesCleartextTraffic` | **true**（为 http WebDAV） | 已知风险：全局允许明文。接受则写入隐私政策与 Release 说明；否则改为仅支持 https |
| `allowBackup` | true | 已接受并写入隐私政策；每次发版核对 `data_extraction_rules.xml` 排除项（crash/covers/novel_text 等） |
| 权限 | INTERNET / ACCESS_NETWORK_STATE / WAKE_LOCK / RECEIVE_BOOT_COMPLETED / FOREGROUND_SERVICE | 每次发版生成 `permissions.txt` 与上一版对比，新增权限必须解释 |
| 导出组件 | 小部件 receiver 等 | 只导出必要项；新增 `exported=true` 需复核 |
| 签名方案 | v2（minSdk 26） | 与 `SIGNING.txt` 指纹一致 |

## 8. 产物归档

- 机器上：`dist/release/vX.Y.Z/`（APK、AAB、mapping、SHA256SUMS、SIGNING、RELEASE_NOTES、permissions.txt）
- 私有备份：整目录复制到离线盘/私有网盘，**保留最近 3 个版本 + 全部 mapping**
- 公开侧：只保留 APK、SHA256SUMS、SIGNING 与 Release 正文
- `dist/` 已被 `.gitignore` 排除；不要为了“方便”提交

- [ ] 从公开 URL 下载 APK，SHA-256 与 `SHA256SUMS.txt` 一致
- [ ] 安装到干净设备：包名、版本号、签名指纹正确

- [ ] 隐私政策 URL 可打开
- [ ] Release 说明里的安装步骤与当前签名状态一致

## 10. 热修、回滚与密钥泄露

**热修**

1. 从 `main` 拉 `hotfix/x.y.z`
2. 只改问题本身
3. 版本号 PATCH +1，走完整流程
4. Release 写明影响范围与是否需要重装

**回滚**

- 商店：回退上一版 APK/AAB
- GitHub：不删除旧 Release，在最新 Release 顶部标注“建议使用 x.y.z”
- 已发布 tag 不动；回滚 = 发更高版本号

**密钥泄露应急**

1. 立即停止发版，撤销可能泄露的 GitHub token / PAT
2. 判定范围：私钥文件、口令、证书指纹是否外泄
3. 签名私钥泄露无法“换钥升级”（同包名签名必须一致）：需公告、联系商店、以新包名迁移
4. 仅口令泄露：`keytool -storepasswd` 更换并重新备份，私钥文件重新加密拷贝
5. 复盘：泄露路径、是否进入 git 历史（进入即视为永久泄露）

## 11. GitHub 仓库安全设置（一次性 + 每次新仓库）

- [ ] 账户开启 2FA
- [ ] Secret scanning + Push protection（公开仓库免费）
- [ ] Immutable releases（若可用）
- [ ] 保护 `main`：禁止 force push；可选要求 PR
- [ ] 保护 tag `v*`：禁止删除/移动
- [ ] PAT 用 fine-grained：仅本仓库、仅 contents/issues 必需权限、设置过期
- [ ] 不在 Actions 日志中打印密钥；必要时用 `::add-mask::`

## 13. 渠道节奏

1. GitHub Release 先发（可回退、可改说明）
2. 酷安 3~7 天观察，收集崩溃日志
3. 无 P0/P1 后上国内商店与 Play
4. 每个渠道使用**同一 tag、同一签名**的包

---

## 14. 反馈闭环

- Issue 一律走模板，崩溃日志必填
- P0（闪退/丢数据）24 小时内回应；P1 一周内给结论
- 修复后在 Release 与 Issue 中互相链接
- 安全报告走私密渠道，见 `.github/SECURITY.md`

## 15. 自动检查脚本

`scripts/check-release-safety.ps1` 覆盖：

1. 工作区是否干净
2. 是否有敏感文件被 git 跟踪
3. 是否有字面口令 / 私钥 / token
4. 密钥与口令文件是否在本机
5. `.gitignore` 是否覆盖关键路径
6. 版本号公式、tag 是否已存在、versionCode 是否递增
7. APK 是否可调试、签名是否通过、版本号是否一致、权限与上一版对比
8. mapping 是否归档
9. 远端是否已发布、HEAD 是否已推送

用法：

```powershell
# 本地检查（还没推 tag 时）
powershell -ExecutionPolicy Bypass -File scripts\check-release-safety.ps1 -SkipRemote

# 完整检查（含远端）
powershell -ExecutionPolicy Bypass -File scripts\check-release-safety.ps1
```

退出码非 0 表示存在阻断项，不要继续打 tag。
