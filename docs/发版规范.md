# Inkvol 发版规范

> 适用范围：`main` 分支、Git tag、GitHub Release、以及后续所有商店渠道。
> 单一真源：版本号在 `gradle.properties`，构建在 `scripts/build-release.ps1`，更新记录在 `CHANGELOG.md`。

---

## 1. 版本号

| 项 | 规则 |
|---|---|
| 命名 | 语义化版本 `MAJOR.MINOR.PATCH` |
| versionName | `1.0.0`、`1.0.1`、`1.1.0` |
| versionCode | `MAJOR*10000 + MINOR*100 + PATCH`，1.0.0 → `10000`，1.0.1 → `10001` |
| 唯一来源 | `gradle.properties` 的 `INKVOL_VERSION_CODE` / `INKVOL_VERSION_NAME` |
| 禁止 | 在 `build.gradle.kts`、脚本、文档里硬编码版本号 |

**何时升位**

- PATCH：修 bug、文案、兼容性，不改数据结构
- MINOR：新增功能、新格式支持，向后兼容
- MAJOR：数据结构或行为不兼容（备份格式、同步协议）

---

## 2. 分支与 tag

- `main` 始终可发布，禁止直接在上面做未验证的大改
- 功能分支：`feat/<简述>`；修复：`fix/<简述>`；热修：`hotfix/<版本号>`
- 合并方式：快进或 squash，保持 `main` 线性可读
- tag：**附注 tag**，命名 `vX.Y.Z`，只打一次
- **已推送的 tag 永不重打、永不删除**；发现打错就发下一个版本

---

## 3. 提交信息

前缀 + 一句话说明，正文写“为什么”和影响面：

```
feat: 支持 7z/CB7 内嵌图片索引
fix: 修复 PDF 关闭后读取页数崩溃
docs: 补充发版规范
chore: 清理未使用依赖
release: 1.0.1
```

---

## 4. 发版流程

```powershell
# 1) 改版本号
#    gradle.properties: INKVOL_VERSION_CODE / INKVOL_VERSION_NAME

# 2) 更新 CHANGELOG.md（新增/修复/已知问题）

# 3) 构建（APK + AAB + mapping 归档 + SHA256）
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1

# 4) 核对产物
$bt='D:\Android\sdk\build-tools\34.0.0'
& "$bt\aapt2.exe" dump badging app\build\outputs\apk\release\app-release.apk |
  Select-String 'package:|application-label|uses-permission|debuggable'
& "$bt\apksigner.bat" verify --print-certs app\build\outputs\apk\release\app-release.apk

# 5) 回归（见第 8 节清单）

# 6) 提交 + 打 tag + 推送
git add -A
git commit -m "release: 1.0.1"
git tag -a v1.0.1 -m "Inkvol 1.0.1"
git push origin main
git push origin v1.0.1

# 7) 创建 Release（资产见第 5 节）
gh release create v1.0.1 --title "Inkvol 1.0.1" --notes-file <notes.md> --latest <资产...>
```

Release 正文统一包含：版本号、变更摘要、安装说明（含“旧测试包需卸载”）、SHA256、签名指纹、源码 tag 链接、已知限制、反馈方式。

## 5. 安全边界：什么能上传，什么不能

### 5.1 可以进入公开仓库

| 内容 | 说明 |
|---|---|
| 源码、资源、gradle 配置 | 不含口令 |
| `LICENSE` / `assets/legal/gpl-3.0.txt` | GPL 分发要求 |
| `CHANGELOG.md`、`README.md`、`docs/*.md` | 内部交接文档 `docs/handoff*.md` 除外 |
| `scripts/*.ps1` `scripts/*.py` | 必须 ASCII、不含密钥与本机绝对路径 |
| `.github/ISSUE_TEMPLATE`、`SECURITY.md` | 反馈与安全渠道 |
| 图标源与生成脚本 | 无版权争议的原创素材 |

### 5.2 严禁进入公开仓库（也不要在 Issue/PR 里贴）

| 内容 | 原因 |
|---|---|
| `keystore/inkvol-release.jks`、`keystore.properties`、任意 `*.jks` / `*.keystore` | 签名私钥泄露 = 任何人都能冒充发布更新 |
| `local.properties` | 含本机 SDK/路径 |
| `dist/`、`app/build/`、`build/`、`.gradle/` | 产物与缓存；`mapping.txt` 会降低逆向门槛 |
| `logs/`、`build_log*.txt`、崩溃日志 | 可能含书名、路径、设备标识 |
| `backups/`、`backup/`、`*.db`、`inkvol-backup*.json` | 真实书库与阅读记录 |
| `test_samples/`、真实书籍/漫画、含版权内容的截图 | 版权与隐私 |
| `tools/` | 本地工具、含本机路径的脚本、第三方源码快照 |
| WebDAV 账号/应用密码、GitHub token、`gh` 凭据 | 直接盗号/盗数据 |
| 带个人路径的截图、录屏 | 暴露用户名与目录结构 |

### 5.3 Release 资产怎么选

| 资产 | 是否公开上传 | 说明 |
|---|---|---|
| `Inkvol-X.Y.Z.apk` | ✅ 必须 | 用户安装 |
| `Inkvol-X.Y.Z.aab` | ⚠️ 可选 | 仅 Play 需要，公开无收益 |
| `mapping-X.Y.Z.txt` | ❌ 不建议 | 混淆映射会帮助逆向；只做私有归档 |
| `SHA256SUMS.txt` | ✅ | 校验完整性 |
| `SIGNING.txt`（证书指纹） | ✅ | 供用户核对，防山寨包 |
| 源码 | ✅ 通过 tag 提供 | GPL 要求“同版本源码”，不要再传 zip |

> 历史处理：`v1.0.0` 曾上传过 `mapping-1.0.0.txt`，已于 2026-11-25 从公开 Release 删除，仅保留私有归档。
> 其他已发布版本如误传，用 `gh release delete-asset <tag> <文件名>` 清理。

### 5.4 上传前自检

```powershell
# 工作区是否有不该提交的东西
git status --short

# 是否误跟踪敏感文件（应为空）
git ls-files | Select-String 'keystore|\.jks|local\.properties|\.db$|test_samples|^dist/|^logs/'

# 最近提交是否带入口令（人工复核命中项）
git grep -n -i -E 'storePassword|keyPassword|BEGIN (RSA|PRIVATE) KEY|ghp_|github_pat_'

# Release 资产清单
gh release view v1.0.0 --json assets --jq '.assets[].name'
```

### 5.5 密钥保管

- `keystore/inkvol-release.jks` 与口令**分开存放**，各两份（一份离线）
- 换机/重装后先用旧包验签，确认密钥可读再发版
- 将来接 CI：密钥以 base64 存 GitHub Secrets，构建时临时落盘并在任务结束删除；**不得**写进仓库或日志

## 6. 产物归档

- 机器上：`dist/release/vX.Y.Z/`（APK、AAB、mapping、SHA256SUMS、SIGNING、RELEASE_NOTES）
- 私有备份：整目录复制到离线盘/私有网盘，**至少保留最近 3 个版本 + 全部 mapping**
- 公开侧：只保留 APK、SHA256SUMS、SIGNING 与 Release 正文
- `dist/` 已被 `.gitignore` 排除，不要为了“方便”把它提交上去

---

## 7. 热修与回滚

**热修**

1. 从 `main` 拉 `hotfix/x.y.z`
2. 只改问题本身，不夹带新功能
3. 走完整发版流程，版本号 +1（PATCH）
4. Release 正文写明“修复了什么、影响哪些用户、是否需要重装”

**回滚**

- 商店：上传上一版 APK/AAB，或使用商店的“版本回退”
- GitHub：不删除旧 Release，在最新 Release 正文顶部标注“建议使用 x.y.z”
- 已发布 tag 不动；回滚 = 发一个更高版本号

## 8. 发版前回归清单

**R8 / release 专项**

- [ ] 备份导出 → 恢复
- [ ] 后台扫描（WorkManager）
- [ ] 桌面小部件
- [ ] ZIP/CBZ、7z/CB7、RAR4/RAR5、PDF、TXT、EPUB、MOBI
- [ ] 首启隐私同意、应用锁、空间清理、崩溃日志分享
- [ ] WebDAV 同步（有账号时）
- [ ] `debuggable=false`、签名证书与 `SIGNING.txt` 一致

**体验**

- [ ] 竖/横、分屏、折叠、平板侧栏、大字体、深色
- [ ] 冷启动、开书、连点翻页
- [ ] 崩溃后重进恢复进度

---

## 9. 渠道节奏

1. GitHub Release 先发（可回退、可改说明）
2. 酷安 3~7 天观察，收集崩溃日志
3. 无 P0/P1 后上国内商店与 Play
4. 每个渠道使用**同一 tag、同一签名**的包

---

## 10. 反馈闭环

- Issue 一律走模板，崩溃日志必填
- P0（闪退/丢数据）24 小时内回应；P1 一周内给结论
- 修复后在 Release 正文与 Issue 中互相链接
- 涉及安全的报告走私密渠道，见 `.github/SECURITY.md`
